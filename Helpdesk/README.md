# Helpdesk

This section documents my development of practical IT support and helpdesk skills.

The focus is on handling technical problems in a structured way:

- Gathering the right information
- Identifying the most likely cause
- Testing possible causes systematically
- Recording troubleshooting steps clearly
- Explaining the resolution in a way that is useful to both users and other technicians

## Troubleshooting Approach

When troubleshooting an issue, I aim to:

1. Understand the issue from the user's perspective.
2. Establish the impact and urgency.
3. Gather relevant information.
4. Reproduce the issue where possible.
5. Identify the most likely causes.
6. Test potential causes systematically.
7. Apply the appropriate resolution.
8. Confirm that the issue is resolved.
9. Document the investigation and resolution.
10. Escalate when the issue is outside my scope or requires additional access.

## Ticket Documentation

A useful support ticket should clearly show:

- User and affected system
- Date and time
- Problem description
- Business impact
- Priority
- Symptoms and error messages
- Troubleshooting performed
- Findings
- Resolution
- Follow-up actions
- Escalation details where applicable

The aim of these exercises is to show how I approach real-world IT issues in practice, rather than simply listing theoretical knowledge.
