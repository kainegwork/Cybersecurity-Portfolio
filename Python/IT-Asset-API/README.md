# IT Asset Management API

A small Python REST API developed as a hands-on learning project using FastAPI and Pydantic. It manages a fictional list of IT devices and demonstrates basic CRUD operations, input validation and HTTP error responses.

## What I built

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/` | Health/status message |
| GET | `/assets` | List all assets |
| GET | `/assets/{asset_id}` | Find a single asset |
| POST | `/assets` | Add an asset |
| PATCH | `/assets/{asset_id}` | Update an asset's status |
| DELETE | `/assets/{asset_id}` | Remove an asset |

Asset data contains an integer ID, hostname and status. The allowed statuses are `Active`, `In Storage`, `Inactive`, `Under Repair` and `Retired`.

Pydantic validates that IDs supplied when creating assets are positive and that hostnames are not empty. A custom `field_validator` trims surrounding whitespace before hostname validation, and invalid input is rejected with HTTP 422. The application also raises HTTP 404 for missing assets and HTTP 409 for duplicate IDs.

## Running locally

Requires Python 3.10+ and a terminal.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
fastapi dev main.py
```

On Windows, activate the environment with `.venv\Scripts\activate` instead. Visit `http://127.0.0.1:8000/docs` for interactive API documentation.

### Example request

`POST /assets`

```json
{
  "id": 3,
  "hostname": " LAPTOP-003 ",
  "status": "Active"
}
```

The returned hostname will be `LAPTOP-003` with leading and trailing whitespace removed.

## Current limitations and next steps

- **In-memory storage only:** Assets are held in a Python list and modifications disappear when the server reloads or restarts. This is a prototype, not a production inventory system.
- IDs are supplied by clients rather than generated by a database.
- PATCH currently updates the status field only.
- No authentication, database integration or automated test suite is included yet.

Next steps are automated tests, persistent storage and exploring integration with a separate fictional SQL Server asset database.
